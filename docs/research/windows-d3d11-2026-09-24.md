# Jackstay on Windows: current state and a D3D11 route (2026-09-24)

Research for the Windows end-to-end map (Wheelhouse). Host: Beaufort, Windows 11
26200, Rust MSVC. Base revision `64a1a21`. Builds on the earlier
[Porthole graphics handoff research](https://github.com/flotilla-org/porthole/blob/6747978f57208689c8ff305052b35f9c7a103a4d/docs/research/windows-parity-graphics.md).
Reference: [wcap](https://github.com/mmozeiko/wcap) `aa25ccb` (public domain).

## Source: Windows gaps

- `lib.rs`: bootstrap, fdpass, `ffi_acquisition`, `ffi_bootstrap`, `ffi_input`
  are Unix-only; Windows `daemon` stub returns unsupported.
- `acquisition.rs`: `arena` Unix-only; `socket` macOS/Linux-only.
- Arena Unix mechanisms: `arena/wait.rs` (UnixStream pair + `poll` wakeups),
  `arena/process.rs` (kqueue/pidfd exit watch), `acquisition/socket.rs`
  (SCM_RIGHTS, peer credentials).
- `native.rs`: `arena` Unix-only; `ffi_native.rs` macOS/Linux only.
- Placeholders exist: `PayloadKind::D3dSharedResource=3`,
  `FT_NATIVE_HANDLE_D3D12_RESOURCE`, `FT_NATIVE_SYNC_D3D12_FENCE`.

## The backend seam

- Old native ring: `NativeFrameBackend` (`native.rs:122`).
- Lease contract: `ArenaNativeBackend` (`native/arena.rs:22`) adds a pool size
  bound before allocation, bounded allocation, real pool byte footprint, the
  producer's completed value and a producer completion timeline.
- Consumers register a `ReleaseTimeline` (`completed_value`, `notify_at`;
  `arena/cleanup.rs:23`) for deferred release.
- Only macOS implements the arena trait (IOSurface pool, Metal blit,
  `MTLSharedEvent`, XPC setup). Linux PipeWire implements only the old trait.
- C ABI: `ft_acquired_frame` with a 144-byte descriptor (`pool_id`, `slot_id`,
  `fence_id`, `fence_value`, `config_generation`); release via
  `ft_acquired_frame_release` or `_defer_release(timeline, value)`; per-platform
  accessors such as `ft_acquired_frame_macos_resources`.
- macOS capture lives in the host (ScreenCaptureKit in Porthole); PipeWire
  capture lives inside Jackstay.

## Consumers

- Wheelhouse (`ed5b97b`): CPU-only consumer (bootstrap, CPU connection,
  acquire/copy/release, input). Only `build.sh` links Jackstay; `build.bat` does not.
- Katzensteg (`83c1897`): CPU publisher (`ft_cpu_producer`,
  `ft_cpu_setup_server`) and consumer with input. `build.zig:24` panics on
  non-macOS/Linux.
- Both need the Windows CPU arena and setup channel before any D3D11 work.

## Recommended first D3D11 slice (proposal, not validated)

- **Capture: Windows.Graphics.Capture.** Windows and monitors, works in RDP
  sessions, cursor/border control. Desktop Duplication is per-output and
  historically problematic under RDP (to verify). The host authorizes the
  source and hands over the capture item, matching PipeWire's
  already-authorized connection rule.
- **From wcap** (`wcap_screen_capture.h`, `wcap_encoder.h`): free-threaded frame
  pool of 2 BGRA8 buffers on a background thread; `IsCursorCaptureEnabled`,
  `IsBorderRequired`, `MinUpdateInterval`; copy each frame into owned textures
  immediately (crop box for client area) and return the WGC buffer — never
  lease WGC buffers; recreate the pool on content-size change as a Jackstay
  reconfiguration generation; `Closed` is terminal. wcap's encoder keeps 8
  output textures in a bitmask, returns slots via `IMFTrackedSample` and drops
  frames with a discontinuity flag when none is free — the same shape as
  Jackstay leases plus drop policy. Do not copy its single-device
  `ID3D11Multithread`/Flush synchronisation, which is same-process only.
- **Pool:** Jackstay-owned bounded pool of `ID3D11Texture2D` with
  `SHARED|SHARED_NTHANDLE`, exported via `IDXGIResource1::CreateSharedHandle`.
- **Handle transfer:** named pipe with host-supplied DACL; server verifies the
  client via `GetNamedPipeClientProcessId` and opens the process to watch its
  lifetime; producer duplicates handles into the verified consumer, which
  acknowledges. No shared names, no raw HANDLE values as bytes.
- **Sync:** shared `ID3D11Fence` timelines (copy then signal, as the macOS
  blit+signal). `notify_at` maps to `SetEventOnCompletion` plus a thread-pool
  wait. Consumers register their own shared fence for release. Keyed mutexes
  give exclusive access only and do not fit multi-consumer leases.
- **Adapters:** grants carry the adapter LUID; mismatched consumers are
  rejected or fall back to CPU. Rename the C constants to D3D11 fence.

Provable on one box: separate producer/consumer processes, holds, kills, live
WGC over RDP. Cross-host needs a Mac peer.

## Encoded path (later)

Porthole's `jackstay-bridge` pins Jackstay `7eda143`, is VideoToolbox-only and
gated to `backend-macos`; `wire.rs` is Unix-only only because the arena is.
Windows egress: Media Foundation hardware H.264/HEVC (`IMFTransform`, async,
`DXGIDeviceManager`) fed NV12/P010 from wcap-style compute conversion; release
the lease when the encoder is done (`IMFTrackedSample`) through deferred
release. Ingress: MF decode into D3D11 and republish. Codec choice via
`jackstay-graph` capabilities.

## Proposed packets

1. (S) Test hygiene: OS RNG for `mint_token`, rename/manifest the "setup" test
   binary, run `cargo test` in Windows CI.
2. (M) Windows shared memory (pagefile-backed `CreateFileMappingW`/`MapViewOfFile`).
3. (M–L) Arena OS layer: event waits, process-handle exit watching,
   handle-based mappings; enable `acquisition::arena` on Windows.
4. (L) Pipe setup channel plus C ABI for CPU setup, bootstrap and input.
   Unblocks Wheelhouse and Katzensteg on CPU.
5. (L) `backend-windows` D3D11 arena backend.
6. (M) C ABI accessors plus a Windows D3D11 reference viewer.
7. (M) WGC capture helper and Porthole handoff; resize, lock and RDP behaviour.
8. (M each) Wheelhouse D3D11 import; Katzensteg Windows endpoints.
9. (L) Media Foundation bridge: loopback, then cross-host.
